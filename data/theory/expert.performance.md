# Оптимизация производительности

Быстрый запрос читает как можно меньше данных и делает как можно меньше лишней работы. Проверяйте гипотезы через `EXPLAIN QUERY PLAN`.

## 1. Условия, совместимые с индексом (sargable)

| Медленно | Быстро |
|----------|--------|
| `WHERE substr(order_date, 1, 4) = '2023'` | `WHERE order_date >= '2023-01-01' AND order_date < '2024-01-01'` |
| `WHERE price * 1.2 > 600` | `WHERE price > 500` |
| `WHERE lower(email) = ?` | индекс по выражению или хранение email в нижнем регистре |

## 2. Агрегируйте до соединения

Соединение двух «многих» сторон перемножает строки. Сначала сожмите каждую сторону:

```sql
WITH items AS (SELECT order_id, COUNT(*) AS n FROM order_items GROUP BY order_id)
SELECT o.id, i.n FROM orders o JOIN items i ON i.order_id = o.id;
```

## 3. Окно вместо коррелированного подзапроса

```sql
-- для каждой строки выполняется подзапрос
SELECT name, price,
  (SELECT AVG(price) FROM products p2 WHERE p2.category_id = p.category_id) AS avg_cat
FROM products p;

-- один проход с окном
SELECT name, price, AVG(price) OVER (PARTITION BY category_id) AS avg_cat
FROM products;
```

## 4. EXISTS вместо COUNT

`EXISTS` останавливается на первом совпадении, а `COUNT(*) > 0` считает все строки.

## 5. UNION ALL вместо UNION

`UNION` удаляет дубликаты — это сортировка или хеширование всего результата. Если дубликатов быть не может (или они нужны), используйте `UNION ALL`.

## 6. Покрывающие индексы и LIMIT

- Если все нужные столбцы есть в индексе, таблицу читать не нужно (`USING COVERING INDEX`).
- Индекс в порядке `ORDER BY` + `LIMIT` позволяет прочитать только первые N строк.

## 7. Фильтруйте как можно раньше

Условия, которые отсекают строки, ставьте во внутренние CTE и подзапросы, а не в самый конец конвейера.
