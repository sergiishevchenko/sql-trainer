# Оптимизация запросов

Быстрый запрос читает **меньше данных** и делает **меньше работы**. Вот основные приёмы.

## 1. Выбирайте только нужные столбцы

`SELECT *` тянет все столбцы, мешает использовать покрывающие индексы и ломается при изменении схемы.

## 2. Фильтруйте как можно раньше

Условия на строки — в `WHERE`, а не в `HAVING`:

```sql
-- хуже: группирует все строки, потом отбрасывает
SELECT status, COUNT(*) FROM orders GROUP BY status HAVING status <> 'cancelled';
-- лучше
SELECT status, COUNT(*) FROM orders WHERE status <> 'cancelled' GROUP BY status;
```

## 3. Не оборачивайте индексируемый столбец в функцию

```sql
-- индекс по order_date не используется
WHERE strftime('%Y', order_date) = '2024'
-- индекс используется
WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01'
```

То же касается `LOWER(col) = …`, `col + 1 = …`, `LIKE '%текст'`.

## 4. EXISTS вместо COUNT для проверки наличия

```sql
-- считает все строки
WHERE (SELECT COUNT(*) FROM orders o WHERE o.customer_id = c.id) > 0
-- останавливается на первой
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id)
```

## 5. Избегайте коррелированных подзапросов в SELECT для больших таблиц

Один `JOIN` с предварительно агрегированной таблицей обычно быстрее, чем подзапрос на каждую строку.

## 6. UNION ALL вместо UNION

Если дубликатов нет или они не мешают, `UNION ALL` не тратит время на их удаление.

## 7. Агрегируйте до соединения

Соединять 1 000 агрегированных строк дешевле, чем 1 000 000 исходных.

## Измеряйте

Проверяйте план выполнения (`EXPLAIN QUERY PLAN`) и время. Оптимизация без измерений — гадание.
