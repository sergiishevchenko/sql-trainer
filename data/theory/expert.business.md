# Сложные бизнес-кейсы

Бизнес-задача редко формулируется в терминах SQL. Первый шаг — перевести её в **метрику с точным определением**.

## От вопроса к запросу

1. **Определите сущность.** Что считаем: клиентов, заказы, деньги?
2. **Определите период и фильтры.** Учитываются ли отменённые заказы? Какой интервал дат?
3. **Определите формулу.** Выручка = `SUM(quantity * unit_price)`? С учётом скидки?
4. **Проверьте крайние случаи.** NULL, нулевые знаменатели, клиенты без заказов.

## Типовые метрики

| Метрика | Формула |
|---------|---------|
| Средний чек (AOV) | выручка / число заказов |
| Повторные покупки | клиенты с ≥ 2 заказами / все покупатели |
| Выполнение плана | факт / план × 100 % |
| Маржа | (цена − себестоимость) × количество |
| Отток | клиенты без активности за период / все клиенты |

## План-факт

```sql
WITH fact AS (
  SELECT rep_id, strftime('%Y-%m', sale_date) AS month,
         SUM(quantity * unit_price * (1 - discount)) AS revenue
  FROM sales JOIN products p ON p.id = sales.product_id
  GROUP BY rep_id, month
)
SELECT t.rep_id, t.month, t.target_amount, COALESCE(f.revenue, 0) AS revenue,
       ROUND(100.0 * COALESCE(f.revenue, 0) / t.target_amount, 1) AS completion_pct
FROM monthly_targets t
LEFT JOIN fact f ON f.rep_id = t.rep_id AND f.month = t.month;
```

`LEFT JOIN` от плана гарантирует, что продавцы без продаж тоже попадут в отчёт.

## ABC-анализ

Товары сортируют по выручке и считают накопленную долю: до 80 % — группа A, до 95 % — B, остальное — C.

```sql
CASE WHEN cum_pct <= 80 THEN 'A' WHEN cum_pct <= 95 THEN 'B' ELSE 'C' END
```

## RFM-сегментация

Recency (давность последней покупки), Frequency (частота), Monetary (сумма). Каждый показатель разбивают на группы через `NTILE` или пороги `CASE`, затем комбинируют.

## Правила хорошего отчёта

- Явные имена столбцов (`revenue`, `completion_pct`).
- Округление только в финальном `SELECT`, а не в промежуточных расчётах.
- Однозначная сортировка.
- Сущности без фактов (продавец без продаж) не теряются.
